# IAHR-APD 홈페이지 — 사무국 인수인계 문서

이 문서 하나만 읽으면 홈페이지를 운영할 수 있습니다. 웹 지식은 필요 없습니다.
후임자에게 이 문서와 아래 계정 정보를 함께 넘겨주세요.

---

## 1. 한 장 요약

| 무엇을 | 어디서 | 누가 |
|---|---|---|
| 뉴스 올리기, 위원 교체, 사진 추가 | `https://app.pagescms.org` | 사무국 담당자 |
| 메뉴 추가, 디자인 변경 | GitHub 저장소를 개발자에게 전달 | 개발자 누구나 |
| 도메인 갱신 (**연 1회, 놓치면 사이트가 내려갑니다**) | 가비아 | 사무국 담당자 |

**필요한 계정은 두 개뿐입니다 — GitHub과 가비아.**
호스팅, 관리자 화면, 인증서 모두 무료이고 별도 가입이 없습니다.
**비용은 도메인 갱신비(연 2만원 내외)뿐입니다.**

---

## 2. 계정

| 서비스 | 용도 | 계정 |
|---|---|---|
| 가비아 | `iahrapd.org` 도메인 | (기입) |
| GitHub | 홈페이지 원본 보관 + 호스팅 + 자동 배포 | `IAHR-APD` 조직 / (기입) |

저장소: **https://github.com/IAHR-APD/iahrapd.org**

> **인수인계 시 반드시 확인할 것**
> 1. 가비아 도메인 **자동 갱신이 켜져 있는지**, 결제 카드가 유효한지
> 2. GitHub **조직(IAHR-APD)의 Owner가 두 명 이상**인지 — 한 명뿐이면 그 사람이
>    퇴사할 때 조직 전체가 잠깁니다. 후임자를 Owner로 추가하세요
> 3. 후임자가 저장소에 **Write 권한**이 있는지 (이게 곧 관리자 화면 권한입니다)

### 편집자 추가·삭제

GitHub 저장소 → **Settings → Collaborators and teams → Add people**

여기에 추가된 사람만 관리자 화면에 로그인할 수 있습니다.
**별도의 홈페이지 계정은 없습니다.** 사람이 나가면 여기서 빼면 편집 권한도 같이 사라집니다.

## 3. 일상 업무 — 관리자 화면

**https://app.pagescms.org** 에 접속 → **Sign in with GitHub** →
저장소 목록에서 **IAHR-APD / iahrapd.org** 선택

왼쪽 메뉴에서 고칠 항목을 고르고, 내용을 바꾼 뒤 **Save** 를 누릅니다.
**2~3분 뒤 실제 사이트에 반영됩니다.** 별도의 업로드나 배포 작업은 없습니다.

> 반영이 되고 있는지 보려면 GitHub 저장소의 **Actions** 탭을 여세요.
> 노란 점 = 작업 중, 초록 체크 = 반영 완료, 빨간 X = 실패.

### 뉴스 올리기

1. 왼쪽 **News** → **Add an entry**
2. 날짜 / 제목 / 요약 / 본문을 채웁니다
   - **Summary** 는 첫 화면과 뉴스 목록에 나옵니다. 한두 문장으로.
   - **Body** 는 비워도 됩니다. 굵게·링크 등 서식을 쓸 수 있습니다.
3. **Save**

첫 화면에는 최신 3건이 자동으로 올라갑니다. 지우려면 해당 글을 열고 삭제하세요.

### 위원 명단 교체 (2년마다)

1. **Executive Committee**
2. **Term** 을 새 임기로 (예: `2027 – 2028`)
3. **Chair and Vice-Chair** 에서 회장·부회장 수정
4. **Members** 목록에서 위원을 추가·삭제·순서 변경
   - 사진은 각 항목의 **Photograph** 에서 올립니다
   - **Secretary General 은 항상 목록의 맨 마지막**에 두세요
   - **Needs checking** 칸은 비워 두세요. 글자를 넣으면 소속 옆에 주황색 경고 표시가 붙습니다
5. **Past terms** 에 이전 임기 추가
6. **Save**

### 갤러리에 행사 사진 추가

1. **Gallery** → **Years** 에서 새 연도 추가
   - Year: `2028` / Event: `26th IAHR-APD Congress`
   - Dates and place: `8 – 12 February 2028 · Wellington, New Zealand`
2. 그 안의 **Photographs** 에 사진을 한 장씩 올립니다
   - **Photograph**: 큰 사진 (클릭하면 확대되는 이미지)
   - **Small version**: 비워 두면 큰 사진을 그대로 씁니다.
     한 연도에 사진이 20장을 넘으면 목록이 느려지니, 그때는 작은 버전도 넣어주세요
   - **Caption**: 설명. 비워도 됩니다
3. 최신 연도를 목록 맨 위로 올립니다
4. **Save**

연도와 사진은 몇 개든 늘릴 수 있습니다. 상단 연도 바로가기 버튼은 자동으로 생깁니다.

### By-Laws와 연차보고서 (웹페이지로 발행)

규정과 연차보고서는 이제 **PDF 다운로드가 아니라 홈페이지에서 바로 읽힙니다.**

**By-Laws, statements and reports** 메뉴에서 편집합니다.

- **Kind** — `statute` 는 About 페이지에, `report` 는 Governance 페이지에 나옵니다
- **Status** — 규정에만 `In force` 를 씁니다. 연차보고서는 비웁니다
- **Edition or year** — 예: `Revised edition, 2025`, `2025`
- **Order** — 숫자가 작을수록 목록 위로 올라갑니다
- **Text** — 본문입니다. 블록을 하나씩 추가합니다
  - `heading` = 조항 제목 (예: `3. Aim`)
  - `text` = 문단
  - `list` = 글머리 목록 (Items 에 한 줄씩)
- **Earlier editions** — 개정으로 대체된 옛 판입니다. **최신판만 본문으로 보이고, 옛 판은 페이지
  맨 아래에 PDF 링크로 남습니다.** 규정을 개정하면 본문을 새 내용으로 갈아끼우고, 옛 판을
  여기에 한 줄 추가하세요

### 첫 화면 배경 사진

**Home page photographs** 메뉴. 사진들이 7초 간격으로 교차됩니다.

- 사진을 추가·삭제하거나 순서를 바꿀 수 있습니다. 개수 제한은 없습니다
- **Place / Region** 은 사진 아래 캡션에 표시됩니다
- 가로로 긴 사진(가로:세로 = 약 2.4:1)이 가장 잘 맞습니다
- **Seconds between photographs** 로 교차 간격을 바꿉니다

### 총회 정보, 수상자, 문서

- **Congresses** — 다음 총회, 최근 총회, 1회부터의 전체 아카이브, 논문집 링크
  - 총회가 끝나면: `Next congress` 를 다음 회차로 바꾸고, `Most recent congress` 를 방금 끝난
    총회로 옮기고, `Archive` 에서 **Mark as the next congress** 체크를 옮깁니다
  - `Opening day` 가 첫 화면의 D-day 카운트다운에 쓰입니다
- **Awards** — 세 개 상의 수상자 목록. 최근 총회 수상자는 사진까지 넣을 수 있습니다
- **Congress hosting pack** — 총회 유치 안내 PDF 3종
- **Calendar** — 첫 화면 오른쪽 일정 목록
- **Site and Secretariat** — 사무국 주소·전화번호, 문의용 메일 주소

## 4. 문의 연락처

Contact 페이지에는 **문의 폼이 없습니다.** 폼을 두려면 메일을 대신 보내주는 서버가
필요하고, 그러면 계정이 하나 더 늘어납니다. 대신 사무국 주소·전화번호와 담당자를 싣습니다.

**Site and Secretariat → Secretariat → Who to write to** 에서 담당자를 관리합니다.

- 담당자가 바뀌면 여기서 이름과 메일 주소를 고칩니다
- **가능하면 공용 주소를 쓰세요** (예: `apd@kict.re.kr`). 개인 주소를 넣으면 그 사람이
  떠난 뒤에도 홈페이지에 남습니다
- 메일 주소는 페이지 소스에 통째로 들어가지 않도록 두 조각으로 나뉘어 저장되고,
  방문자의 브라우저에서 합쳐집니다. 스팸 수집 프로그램에 대한 최소한의 방어입니다
- **Site and Secretariat → What the Secretariat handles** 에서 "어떤 문의를 받는지"
  목록을 고칠 수 있습니다

> 나중에 문의 폼이 꼭 필요해지면 Formspree 같은 무료 서비스를 붙일 수 있습니다.
> 계정이 하나 늘어나는 대신 주소를 노출하지 않고 폼을 운영할 수 있습니다.

## 5. 사이트가 안 보일 때

**"이 사이트에 연결할 수 없음" / 도메인이 만료됐다는 안내**
→ 도메인 갱신이 안 된 것입니다. 가비아에서 `iahrapd.org` 갱신 여부를 확인하세요.
   **사이트가 내려가는 가장 흔한 원인입니다.**

**수정했는데 반영이 안 됨**
→ GitHub 저장소 → **Actions** 탭에서 최근 작업이 빨간 X 인지 봅니다.
   빨간 X 를 눌러 로그 끝부분의 오류 메시지를 개발자에게 보여주세요.
   대개 직전 수정에서 필수 항목이 비었을 때 발생합니다.
   급하면 관리자 화면에서 그 수정을 되돌리면 자동으로 복구됩니다.

**관리자 화면 로그인이 안 됨**
→ 저장소 Write 권한이 없는 계정입니다. 조직 Owner에게 Collaborator 추가를 요청하세요.

**사진이 안 보임**
→ 사진 파일명에 한글이나 공백이 들어가면 문제가 될 수 있습니다. 영문·숫자·하이픈만
   쓰는 것을 권합니다 (예: `2028-wellington-01.jpg`).

## 6. 개발자에게 넘길 때

GitHub 저장소 주소 하나만 넘기면 됩니다. 저장소 안의 `README.md` 에 구조와
빌드 방법이 정리되어 있습니다.

기억해 둘 점:

- **특정 업체나 도구에 묶여 있지 않습니다.** 내용은 전부 JSON·Markdown 텍스트 파일이라,
  다른 제작 도구로 옮겨도 그대로 가져갑니다
- **외주를 줄 때도** 이 저장소를 그대로 넘기면 됩니다. 콘텐츠를 다시 입력할 필요가 없습니다
- 사이트는 정적 파일이라 서버가 죽거나 해킹당할 표면이 없습니다.
  **관리하는 사람이 없어도 사이트는 그대로 떠 있습니다.** 도메인 갱신만 놓치지 마세요
