# IAHR-APD 홈페이지 — 사무국 인수인계 문서

이 문서 하나만 읽으면 홈페이지를 운영할 수 있습니다. 웹 지식은 필요 없습니다.
후임자에게 이 문서와 아래 계정 정보를 함께 넘겨주세요.

---

## 1. 한 장 요약

| 무엇을 | 어디서 | 누가 |
|---|---|---|
| 뉴스 올리기, 위원 교체, 사진 추가 | `https://www.iahrapd.org/admin/` | 사무국 담당자 |
| 메뉴 추가, 디자인 변경 | GitHub 저장소를 개발자에게 전달 | 개발자 누구나 |
| 도메인 갱신 (**연 1회, 놓치면 사이트가 내려갑니다**) | 가비아 | 사무국 담당자 |

**비용**: 도메인 갱신비(연 2만원 내외)만 듭니다. 호스팅·관리자 화면·문의 메일 모두 무료입니다.

---

## 2. 계정

아래 네 곳의 계정이 필요합니다. **모두 개인 이메일이 아니라 사무국 공용 주소로 만들어 두세요.**
담당자가 바뀌어도 계정이 개인을 따라가지 않아야 합니다.

| 서비스 | 용도 | 계정 |
|---|---|---|
| 가비아 | `iahrapd.org` 도메인 | (기입) |
| GitHub | 홈페이지 원본 보관 | (기입) |
| Cloudflare | 사이트 호스팅, 문의 메일 전달 | (기입) |
| Resend | 문의 메일 발송 | (기입) |

> **인수인계 시 반드시 확인할 것**
> 1. 가비아 도메인 **자동 갱신이 켜져 있는지**, 결제 카드가 유효한지
> 2. GitHub 저장소에 후임자 계정이 **collaborator로 추가**되었는지
> 3. Cloudflare 환경변수 `CONTACT_TO` 가 **현 담당자 메일 주소**인지

## 3. 일상 업무 — 관리자 화면

`https://www.iahrapd.org/admin/` 에 접속해 **GitHub 계정으로 로그인**합니다.
저장소에 권한이 있는 사람만 들어갈 수 있습니다.

왼쪽 메뉴에서 고칠 항목을 고르고, 내용을 바꾼 뒤 **Publish** 를 누릅니다.
**1~2분 뒤 실제 사이트에 반영됩니다.** 별도의 업로드나 배포 작업은 없습니다.

### 뉴스 올리기

1. 왼쪽 **News** → 오른쪽 위 **New News item**
2. 날짜 / 제목 / 요약 / 본문을 채웁니다
   - **요약(Summary)** 은 첫 화면과 뉴스 목록에 나옵니다. 한두 문장으로.
   - **본문(Body)** 은 비워도 됩니다. 굵게·링크 등 서식을 쓸 수 있습니다.
3. **Publish** → **Publish now**

첫 화면에는 최신 3건이 자동으로 올라갑니다. 지우려면 해당 글을 열고 **Delete**.

### 위원 명단 교체 (2년마다)

1. **Executive Committee** → **Committee members**
2. **Term** 을 새 임기로 (예: `2027 – 2028`)
3. **Chair and Vice-Chair** 에서 회장·부회장을 수정
4. **Members** 목록에서 위원을 추가·삭제·순서 변경
   - 사진은 각 항목의 **Photograph** 에서 올립니다
   - **Secretary General 은 항상 목록의 맨 마지막**에 두세요
   - **Needs checking** 칸은 비워 두세요. 여기에 글자를 넣으면 소속 옆에 주황색 경고 표시가 붙습니다
5. **Past terms** 에 이전 임기를 추가
6. **Publish**

### 갤러리에 행사 사진 추가

1. **Gallery** → **Photographs by year**
2. **Years** 목록에서 **Add Years** 를 눌러 새 연도를 만듭니다
   - Year: `2028`
   - Event: `26th IAHR-APD Congress`
   - Dates and place: `8 – 12 February 2028 · Wellington, New Zealand`
3. 그 안의 **Photographs** 에서 **Add Photographs** 로 사진을 한 장씩 올립니다
   - **Photograph**: 큰 사진 (클릭했을 때 확대되는 이미지)
   - **Small version**: 비워 두면 큰 사진을 그대로 씁니다. 사진이 많으면 목록이 느려질 수 있으니, 사진이 20장을 넘으면 개발자에게 작은 버전 생성을 요청하세요
   - **Caption**: 설명. 비워도 됩니다
4. 연도 순서는 목록에서 끌어서 바꿉니다. 최신 연도를 맨 위로.
5. **Publish**

연도와 사진은 몇 개든 늘릴 수 있습니다. 상단 연도 바로가기 버튼은 자동으로 생깁니다.

### 총회 정보, 수상자, 문서

- **Congresses** — 다음 총회, 최근 총회, 1회부터의 전체 아카이브, 논문집 링크
  - 다음 총회가 끝나면: `Next congress` 를 그 다음 회차로 바꾸고, `Most recent congress` 를 방금 끝난 총회로 옮기고, `Archive` 의 해당 행에서 **Mark as next congress** 체크를 옮깁니다
  - `Opening day` 는 첫 화면의 D-day 카운트다운에 쓰입니다
- **Awards** — 세 개 상의 수상자 목록. 최근 총회 수상자는 `Most recent congress` 에서 사진까지 넣을 수 있습니다
- **Other pages → Documents** — By-Laws, 수상 규정, 연차보고서 PDF 업로드
- **Other pages → Calendar** — 첫 화면 오른쪽 일정 목록
- **Other pages → Site and Secretariat** — 사무국 주소·전화번호가 바뀌었을 때

## 4. 문의 메일

Contact 페이지의 문의 폼은 **사무국 담당자 메일함으로 바로 전달**됩니다.

**받는 주소는 홈페이지 어디에도 표시되지 않습니다.** 소스 보기를 해도 나오지 않고,
스팸 수집 프로그램도 긁어갈 수 없습니다. 주소는 Cloudflare 설정에만 저장되어 있습니다.

받는 사람을 바꾸려면:
Cloudflare 대시보드 → **Workers & Pages** → 사이트 선택 → **Settings → Variables**
→ `CONTACT_TO` 값을 새 주소로 수정 → **Save** → **Retry deployment**

## 5. 사이트가 안 보일 때

증상별로 순서대로 확인하세요.

**"이 사이트에 연결할 수 없음" / 도메인이 팔렸다는 안내**
→ 도메인 갱신이 안 된 것입니다. 가비아에 로그인해 `iahrapd.org` 갱신 여부를 확인하세요.
   이것이 사이트가 내려가는 가장 흔한 원인입니다.

**수정했는데 반영이 안 됨**
→ Cloudflare 대시보드 → 사이트 → **Deployments** 에서 최근 배포가 실패(빨간색)했는지 봅니다.
   실패했다면 로그를 개발자에게 보여주세요. 대개 직전 수정에서 필수 항목이 비었을 때 발생합니다.
   급하면 **직전 성공 배포에서 Rollback** 을 눌러 되돌릴 수 있습니다.

**관리자 화면 로그인이 안 됨**
→ GitHub 저장소 권한이 없는 계정입니다. 저장소 관리자에게 collaborator 추가를 요청하세요.

**문의 메일이 안 옴**
→ 스팸함을 먼저 확인. 그래도 없으면 Cloudflare 환경변수 세 개
   (`CONTACT_TO`, `CONTACT_FROM`, `RESEND_API_KEY`) 가 모두 채워져 있는지 확인하세요.

## 6. 개발자에게 넘길 때

GitHub 저장소 주소 하나만 넘기면 됩니다. 저장소 안의 `README.md` 에 구조와
빌드 방법이 정리되어 있습니다.

기억해 둘 점:

- **특정 업체나 도구에 묶여 있지 않습니다.** 내용은 전부 JSON·Markdown 텍스트 파일이라,
  다른 제작 도구로 옮겨도 그대로 가져갈 수 있습니다.
- **홈페이지 제작을 외주 줄 때도** 이 저장소를 그대로 넘기면 됩니다. 콘텐츠를
  처음부터 다시 입력할 필요가 없습니다.
- 사이트는 정적 파일이라 서버가 죽거나 해킹당할 표면이 없습니다. **관리하는 사람이
  없어도 사이트는 그대로 떠 있습니다.** 단 하나, 도메인 갱신만 놓치지 마세요.
